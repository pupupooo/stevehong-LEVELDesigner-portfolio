WHY IT MATTERS

这套工具想加速的，不只是写文档这一个动作。

开放世界关卡策划经常承接大量落地沟通：玩法、空间、美术、灯光、音频、VFX、程序、系统都要从同一份设计中读取不同信息。传统文档即使写得很详细，也很难保证每个职能都能马上找到自己开始工作所需的上下文。

降低文档事务负担

设计师不应该把大量时间消耗在重复整理格式、拆分汇报材料、复制字段、维护多份文档一致性上。结构化记录稳定后，文档和 Deck 应该从同一份内容生成。

结构化设计文件 表单化编辑 自动渲染

降低沟通摩擦

真正耗时的正是职能之间反复确认——“你到底需要我做什么””我现在还缺什么信息”——缺少对他人内部工作的认识。职能接口文件可以提前暴露缺口，把模糊需求转成可追问、可审核、可交付的材料。

职能接口文件 缺口追问 交付前检查
INTERFACE EXAMPLES

接口文件作为协作契约，让协作对象更高效地开始工作。

下面两个样例当前并未真正实现，仅用来说明产品机制和设计目标。成熟形态中，每个接口都应由实际使用它的职能参与校准。

EXAMPLE 01

玩法原型接口：从玩法需求到实现说明

当前流程通常是策划写玩法需求，原型实现同事根据需求制作组件，策划再组装调试；原型过审后还要转成正式开发说明。每一层都可能发生重新解释和反复沟通。

由实现同事维护项目专属蓝图能力库，沉淀可复用组件、实现模式、项目约束和接口要求。
策划在工作台中完成玩法设计后，工具根据蓝图能力库的接口要求生成标准实现说明。
实现同事不再从宽泛设计文档中反推需求，而是审核标准说明，并在关键节点确认实现逻辑。
纯原型阶段可以进一步压缩链路：策划调用经过验证的蓝图能力完成可审查原型，再由接口层转译为正式开发信息。
项目蓝图能力库 玩法需求 -> 实现说明 关键逻辑审核
EXAMPLE 02

灯光接口文件

这个示例的目的：当关卡策划填写结构化设计记录时，工具可以根据”灯光开始工作需要什么信息”提前检查缺口。

已有信息

区域功能、情绪曲线、时间段、关键视线、危险/安全区域、重点事件节点。

开始工作可能需要

主视觉焦点、导航引导、明暗节奏、动态变化条件、美术和 TA 依赖。

工具应追问设计师

哪些区域需要灯光引导？哪些区域必须压迫或迷失？关键事件是否需要状态切换？

必须由灯光/TA 校准

实时光和烘焙光边界、性能预算、后处理依赖、材质响应和平台限制。

`level-design-deck` 已经能把关卡设计拆成结构化设计文件，提供表单编辑、机械校验、跨模块检查，并生成文档、Deck、分镜和检查报告；当前网页版工作台把告警、表单、预览和对话侧栏放在同一页面里。

网页版工作台交互演示

这段演示记录了当前工作台的一次交互迭代：流程图视图已经可以和结构化表单联动，点击节点后自动定位到对应字段，并支持在同一工作台里完成查看、编辑、保存与重新渲染。

网页版工作台把告警栏、结构化表单、HTML 预览和对话侧栏放到同一页面里，设计师不必在命令行、编辑器和浏览器之间来回切换。

STORYBOARD PIPELINE

从故事脚本到可用分镜的 AI 工作流。

这条能力服务于剧本转分镜：把故事脚本、剧情大纲、关卡关键节点、角色参考和场景锚定整理成分镜结构文件，再生成分镜面板、图像生成提示词、反向提示词和关卡调整建议。公开页面只说明机制，不展示真实项目文本。

01 / SCRIPT

脚本素材导入

粘贴故事脚本或剧情大纲，保留原始素材供设计师随时回看，避免分镜设计脱离剧本语境。

02 / BEAT MAP

关卡节点映射

从 bubble_diagram 读取节点，把需要视觉化的关键 Beat 生成 panel 骨架，保证分镜仍然服务关卡流程。

03 / ANCHOR

角色与场景锚定

用 characters、scene_anchors、camera_position 和 char_layout 固定角色外观、场景关系、镜头位置与人物站位。

04 / OUTPUT

提示词与建议导出

批量生成图像提示词和反向提示词，导出关卡调整建议，并把 image-2 生成图回填到对应分镜帧。

Schema 限制先行

镜头景别、构图、镜头手法、镜头物理位置、角色空间布局和逐帧反向提示都进入结构定义，字段存在和含义先被固定。

提示词机械质检

生成过程中遇到过“看屏幕”“两人对峙”等场景的透视错误，因此加入视线关系、角色空间关系、场景矛盾和提示词过长检查。

人工确认门

设计师标记待生成、已完成或需重做，必要时回到字段层调整镜头、站位、场景锚点或反向提示，减少盲目堆提示词。

扩展方向

PRODUCT FORM

产品形态：面向设计师的对话优先工作台。

理想形态中，设计师可以先用对话说明需求；工具负责追问缺失信息、给出执行计划、生成可预览产物，并把关键变化交回设计师确认。当前工作台已接入对话侧栏，扩展方向是让对话更深地写入设计文件、调用检查与生成能力。

产品形态展望

对话只是入口，真正的产品能力在于把对话里的意图转成可维护的结构化设计记录，并用项目知识、职能接口和机械检查不断约束它。

  • 对话优先交互：用追问和计划降低设计师进入成本。
  • 结构化编辑：关键字段回到结构定义和设计记录，而不是散落在长文本里。
  • 可视化检查：把区域关系、流程节点、输出产物和缺口报告放在可审查界面中。
  • 设计师确认：体验判断、关键逻辑和跨职能接口变更必须由人确认。
  • 项目目标对齐层：注入项目目标、约束、模式和参考案例，让新设计不从空白提示词开始。
  • 项目专属蓝图能力库：让经过维护的实现能力进入原型链路，同时保留实现同事的维护和审核权。
