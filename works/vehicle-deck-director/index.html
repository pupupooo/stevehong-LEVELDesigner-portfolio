01 / SCOPE & PROBLEM

从任务清单转向载具玩法体系化。

大世界载具体验需要被拆成不同颗粒度：路过即可感受到的城市触感、能够接入和结算的复合玩法，以及更稀缺的系统级挑战。玩家中心分发与 LLM 调度，则是在这套分层基础上的原型验证方向。

生产侧：体系规划

围绕城市驾驶，规划 T3/T2/T1 三层载具玩法，并推进部分具体玩法设计。

体验侧：反公式化

如果玩法只靠固定触发器，城市很快会变成一组预埋按钮；载具体验需要根据玩家状态和世界语义回应。

探索侧：原型验证

2D MVP 和 Director Lab 用来验证分发节奏、事件接入、世界响应，以及 LLM 的参与边界。

02 / VEHICLE GAMEPLAY PYRAMID

T3 / T2 / T1 对应三种体验颗粒度。

三层玩法对应不同频率和规模：驾驶途中每几秒的城市触感、每几分钟的可接入事件，以及跨越大区时的系统级高光挑战。

T3 载具感官层

1-10 秒的原子交互：连续破坏、街头恶作剧、暴力抄近道、环境反馈。它主要作为城市道路和 POI 的物理语义存在，不进入任务卡组。

T2 载具 Beat 层

当前原型的主体：有触发条件、接入信号、玩家选择、目标、过程反馈和结果。它适合被结构化成 Vehicle Beat，并进入事件池。

T1 系统级挑战

高稀缺的完整体验章节。它调用 T3 的物理交互和 T2 的玩法模组，承担更长线的高压体验组织。

T3 的系统角色

沉淀为区域标签、路段语义、解决手段和风险条件。例如破坏物、近道、积水、玻璃展厅会影响 T2/T1 的可用解法。

T2 的分发验证价值

T2 具备“可识别、可接入、可忽略、可执行、可结算”的完整结构，适合作为 Director 筛选和 LLM 语义推荐的对象。

T1 的验证位置

T1 验证需要更长流程、复杂状态和完整城市资产支撑；2D MVP 仅保留它在载具体系中的层级位置。

T2 事件池样例

午夜竞速、恐吓专车、运钞车、副驾指挥作为 T2 事件池样例，用来验证不同接入方式与世界响应。

项目载具体系先把城市驾驶拆成 T3、T2、T1 三种体验颗粒度。
T2 结构化把复合玩法整理为有上下文、接入、目标、反馈和结算的 Vehicle Beat。
2D MVP用纯 Deck 模拟 T2 事件何时出现、如何接入、如何被忽略。
Director Lab单独展示 LLM 参与后的语义 Beat 推荐、规则裁决和事件池实例化。
设计边界LLM 只提建议，规则层和策划定义的事件池决定什么能真正发生。
完整体验链T3 提供城市触感，T2 负责事件接入，T1 组织更长线的高光挑战。
03 / IMPLEMENTATION PROOF

2D MVP 聚焦 T2 分发验证。

T3 依赖真实城市资产、物理反馈和路段布设；T1 需要更长的任务链、状态管理和系统级压力。当前 MVP 聚焦 T2，用于验证“事件何时出现、如何接入、玩家如何接受/忽略、世界如何回应”。

MVP Demo：纯 Deck 分发模拟

用可玩的 2D 白盒验证 T2 事件的触发节奏、接入信号、接受/忽略和抢车后的世界响应。

Director Lab：LLM 语义调度链

把同一套 T2 事件池放进 world snapshot、LLM Beat 推荐、Director Policy 裁决和事件池实例化链路中，展示 LLM 参与后的职责边界。

04 / WHAT IS IMPLEMENTED

原型验证范围。

这两个原型服务于同一个问题：T2 复合玩法如何被结构化、被筛选、被接入，并在合适的时机推到玩家附近。

目前已验证

  1. T2 分发节奏距离 + 时间计数、空牌、弃牌和重洗，用来测试事件出现频率与接入手感。
  2. Vehicle Beat signalT2 玩法先形成可接入/可忽略的信号，再进入具体玩法，区分“世界找上门”和“玩家主动接取”。
  3. T2 事件池样例午夜竞速、恐吓专车、拦截运钞车、副驾指挥分别覆盖挑战、请求、对峙、护送/指挥等事件族。
  4. 车辆身份与世界响应抢车、车辆类型、热度和区域标签会改变后续推荐，让分发回应玩家行为与所在区域。
  5. LLM 语义调度链Director Lab 展示 world snapshot、LLM 推荐 Beat、Director Policy 裁决和事件池实例化。

暂未验证

  1. T3 真实物理触感真实城市资产、物理破坏、音效和路段布设是 T3 验证所需条件；现阶段保留层级定义与语义入口。
  2. T1 系统级挑战章节完整验证需要更长流程、复杂状态和城市压力系统；在载具体系中承担稀缺高光章节。
  3. 生产级 LLM 接入Director Lab 采用 mock 决策链，重点验证 LLM 的职责边界和输入输出结构。
  4. 完整城市内容规模城区采用白盒源事实，优先保证道路、POI、NPC 生成线和事件锚点一致。
  5. 跨系统长期记忆已验证短期热度、抢车和近期事件响应；长期身份、关系网和生涯线属于更高阶的系统扩展。
05 / LLM-READY DIRECTOR

LLM 负责语义推荐，规则层负责执行边界。

T2 被结构化成 Vehicle Beat 后，LLM 可以读取明确对象：根据世界标签、车辆身份、玩家行为和近期节奏，推荐当前合适的 Beat 类型。随后 Director Policy 处理节奏、重复、道路状态和可执行边界，最终事件仍来自设计好的事件池。

  • T3：作为区域语义、物理解法和风险条件被系统读取。
  • T2：主验证层，被整理成 Vehicle Beat、事件族、接入方式和结果反馈。
  • T1：作为稀缺系统级挑战章节，调用 T3/T2 组织完整体验波段。
  • 2D Demo：使用纯 Deck 抽取模拟分发回路，承担无 LLM 条件下的可玩验证。
  • Director Lab：展示 LLM 参与后的语义推荐、规则裁决和事件池实例化。
  • 设计边界：Deck/Beat 提供玩法边界和节奏框架，LLM 提供语义判断与表现建议，规则层决定什么能发生。
